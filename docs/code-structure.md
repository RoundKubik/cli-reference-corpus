# Reading and extending the code

The design uses small objects with explicit responsibilities and composes them
into the parsing and export workflows. Immutable dataclasses describe inputs and
views. Mutable state belongs to a parsing session or a document being assembled.

## Start here

Follow a normal parse request in this order:

1. `cli.main` reads arguments and selects a vendor profile.
2. `BasePDFParser.parse` opens the PDF and determines the page range.
3. `CommandStream` feeds page events into a `CommandBuilder`.
4. The profile turns the builder's fields into a `Command`.
5. `CorpusWriter` publishes JSON/Markdown pairs, a manifest and a validation report.

The optional `preparation` package is loaded only by the CHM conversion script;
the main parser still needs no HTML dependencies.

## Working conventions

- Name an object after what it represents: `PageRange`, `CommandRecord`,
  `CommandMarkdown`, `HTMLArticle`. Give each object one reason to change.
- Keep orchestration readable as a sequence of named operations. Keep geometry,
  serialization and file publication out of vendor command rules.
- Pass dependencies explicitly. Avoid keeping an open PDF or session state in a
  profile: profiles are copied into worker processes.
- Use simple functions for stateless operations such as JSON I/O and escaping.
  A new interface or class should clarify a real responsibility.
- Preserve the public profile hooks and compatibility entry points:
  `parse_pdf`, `write_corpus`, `render_command`, `export_markdown`, `render_topics`.
  The existing `from cli_reference_corpus.cli import write_corpus` also works.
- Keep changes to extraction rules separate from structural refactoring. Check
  real PDF fixtures, diagnostics, paired files and the refusal to overwrite.

## Verification of this refactoring

The regression suite covers real Huawei/Cisco pages, custom profiles, both JSON
schemas, parallel readers, CHM pagination and cleanup after failed publication.
An additional before/after comparison used 16 real-PDF cases containing 152 commands:
all command fields and reports matched exactly. The new reader and renderer were
also compared against all 14,456 stored command pairs with exact Markdown matches.
The input PDFs and existing corpora were not regenerated by this refactoring.

Cisco example handling is in `vendors/cisco_examples.py`: it combines prompt
recognition with documented syntax/title matching for promptless input, retaining
output in the source text. `scripts/verify_corpora.py` checks saved pairs and
references; `scripts/review_extraction_warnings.py` inventories diagnostics with
source evidence. See the [extraction review](../reports/coverage/extraction-warning-review.md).
